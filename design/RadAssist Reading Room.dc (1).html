# Handoff: RadAssist "Reading Room" UI ## Overview A full visual and interaction redesign of the RadAssist radiology reporting app (`suborhan7/RadAssist-RAG`, branch `main`, frontend at `frontend/src`). RadAssist is a retrieval-augmented chest X-ray reporting assistant: a radiologist uploads a study, the system retrieves the five most similar prior cases from a ChromaDB index, a local Llama 3 8B drafts a report from them, and the radiologist edits and signs it. The existing frontend works but reads as a generic admin dashboard — boxed cards, heavy borders, small crowded type, colour used decoratively. "Reading Room" replaces that with a dark, low-glare reading environment appropriate to a radiology workstation: - Near-black background so film is the brightest thing on screen. - Exactly two accent colours, each with one job: **cyan = retrieval and interaction**, **amber = look here / model is unsupported**. Nothing else is coloured. - Hairline dividers and whitespace instead of cards and boxes. - Large, roomy type (15px base, 34–62px headlines) with generous line-height. - The citation/provenance interaction — superscript case numbers on every clause — is the product's signature and is now a first-class UI element on every report surface. All 15 screens and states are covered. ## About the Design Files `RadAssist Reading Room.dc.html` in this bundle is a **design reference created in HTML** — a prototype showing intended look and behaviour. It is **not production code to copy**. It is a single self-contained HTML file that renders all 15 screens in one canvas with a screen-switcher strip at the top; the real app has these as separate routes. The task is to **recreate these designs in the RadAssist codebase's existing environment** — Next.js App Router + React + Tailwind + the existing `components/ui/*` primitives — using its established patterns. Do not port the prototype's inline styles: translate the values below into the repo's `tokens.css` / `tailwind.config.ts` and build with the repo's component library, extending it where the design needs something that doesn't exist yet. The prototype uses a small custom element, ``, purely as a drag-and-drop placeholder for X-ray images that could not be redistributed. **It has no production equivalent** — everywhere you see ``, the real app renders the actual DICOM/PNG study image from the backend. ## Fidelity **High-fidelity.** Colours, typography, spacing, radii and copy are final and exact. Recreate the UI pixel-perfectly using the codebase's libraries and patterns. Every string in the prototype is intentional — particularly the honesty strings (see *Copy rules* below); do not paraphrase them. The design canvas is a fixed **1440 × 900** frame per screen. Layouts are described at that width.
